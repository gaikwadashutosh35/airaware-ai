## 1. How to read the tables

**Labels:**

| Label | Meaning |
|---|---|
| **OBSERVED** | Seen in a rendered reference page, as recorded in doc 02 with a screenshot or extracted text. The "Observed pattern" column is OBSERVED unless it says "not observed". |
| **RECOMMENDED** | A proposal. The "AirAware feature", "Component / interaction", "Classification" and "Priority" columns are RECOMMENDED. Each one needs the owner's OK before it is built, and any new user-facing string also needs CP-04 approval. |
| **Shipped** | Already in the app, with the source that shows it. |

**ID namespaces.** These follow doc 14's table "ID namespaces".

| ID | Means |
|---|---|
| FA-01… | A row in this file. The prefix is new, so it does not clash with other docs. |
| 02-R1…02-R9 | Doc 02's recommendations (02 §5). |
| Bare R0–R9 | Doc 14's build phases. Every bare R-number in the "Doc 14 phase" column is a phase. |
| D1–D15 | Doc 14's open owner decisions (14 §2). |
| L·, T·, A·, P·, H·, B·, I·, M·, X· | Doc 11's feature rows. |
| S1–S12 | Doc 13's data sources (13 §1). |
| J· | `OWNER_DECISIONS.md` rows. |
| OD B2, OD E1, OD G3, OD H4… | Other `OWNER_DECISIONS.md` rows. The "OD" prefix keeps them apart from doc 11 rows with the same letters. |

**Screenshot paths.** `refs/` means `docs/redesign/audit/screenshots/redesign-2026-11-28/references/`, and `current/` means the sibling `current/` folder. Every file named here was checked against a directory listing on 28 Nov. Both folders are git-ignored (OD I1), so a fresh clone does not have them.

**Text-only evidence.** Some patterns were recorded by doc 02 from extracted page text ("landing text", "landing preview", "link list"), not from a screenshot. Those cells say "extracted text per doc 02" and name the page capture only as the page it came from.

**Classification.** Each row gets exactly one of these:
- UI-only redesign;
- reuse of existing capability (already shipped; no build needed);
- new frontend capability;
- new backend/API requirement;
- new external data requirement;
- future-deferred.

One exception: FA-27 has a client part (a) and a server part (b), each with its own classification. This follows doc 11's rule that a feature needing both is split in two (11 §1.1).

**Priority.** This shows the guide's §5 priority where there is one, and then doc 11's row ID with its Now, Next or Later rating.

**Doc 14 phase.** This comes from doc 14's phase scope lists (§3) and its "Later" table (§4). "Not planned" means doc 14 schedules no build for it.

**A rule that holds for every row.** No row copies a reference's AQI, CPCB or US AQI calculation, its bands or its methodology. AirAware's verdict comes only from the server's `assessAir`, which compares 24-hour model averages with India's limits (`airCheck.ts`, doc 04 §10). The client never re-derives it.

## 7. Patterns not adapted in any form

From doc 02 §1.5, §2.6, §3.6 and §5 ("Not to adopt in any form"), and doc 11 §12. Most were OBSERVED on at least one reference. "Colour scale" and "best time" come from doc 11 §12's rules, not from a reference.

- An AQI number, band, colour scale or toggle. **Never copy a reference's AQI or CPCB calculation**: the alternate site computes a "CPCB AQI" from model data, and UrbanAir and SaafSaans headline an AQI.
- Mixed scales in one phrase, such as "Poor to Very Unhealthy".
- "Cleanest hours", "best time" or "safe" wording, and starters such as "Is it safe to run outside at 7pm?".
- Dose %, "cigarettes' worth" or CO₂ savings without a documented method.
- "Live", "measured", "sensor", "observed" or "telemetry" for model data.
- Health-condition questions in household setup, and per-person medication lines ("keep medication available").
- Weather given as the cause of pollution ("while winds remain low").
- Pre-ticked choices shown as the user's own.
- Sections that stay blank until scrolled into view (see FA-23).
- Spec section numbers in user copy ("§32").
- "Passed" badges that do not come from real test runs.
- A floating AI button over data.
- A sideways-scrolling tab strip that hides tabs on phones.
- Ask text carried in the URL (`?q=`).
- The alternate site's name, look, copy or code. It is called "AirAware AI" too.
